# 《人在高中，我的恋爱系统对吗？》项目说明

## 一、书籍基本信息
- **书名**：《人在高中，我的恋爱系统对吗？》
- **题材**：校园 / 恋爱 / 轻喜剧 / 系统流 / 群像
- **字数目标**：1,000,000 字（100 万）
- **卷数**：10 卷
- **章节**：每卷 25 章，共 250 章
- **单章字数**：约 4,000 字（正文实际会在 3,800–4,400 区间浮动）

## 二、核心卖点
1. **"对吗？"三字梗**：系统每次下达任务都以"……对吗？"结尾，经常给出离谱或误判的判定，主角吐槽不断。
2. **群像而不是单女主**：五位核心女角色（同桌、学姐、青梅、转学生、邻居），主角最终的"真结局"是与某一位确定关系，但前九卷以日常、群像、校园事件为主。
3. **反套路**：主角不追求"把所有妹子都收了"，相反，他想尽办法摆脱系统。系统的每一次"升级"都是对他的一次围堵。
4. **校园感**：月考、体测、运动会、文化节、社团招新、期末、寒暑假——每一卷围绕一个"校园大事件"。

## 四、生成流程（**批次化生产线 v2**）

每一批次 = 5 章连续。完整流水线见 **framework/05_批次化写作工作流.md**：

```
批次 NNN–MMM（连续 5 章）

  ⓪【Primer · 上下文打包】产出 context_pack，后续 subagent 只读它
         ↓
  ①【Ideator · 创意】趣味 / 合理 / 爽点三问，允许反向建议
         ↓
  ②【Gatekeeper · 审核】逐条裁决，合成《00_批次脑暴定稿.md》
         ↓
  ③【写作 subagent】
       · 日常档：单写手 × 5
       · 高能/卷末档：Writer-A/B/C × 3 路 → Synthesizer 合成
         ↓
  ③.5【scripts/scan_ai_templates.py】确定性预筛，产 AI 味命中清单
         ↓
  ④【审查并发层】同时跑：
       · 硬校验 × 5
       · 润色-节奏 × 5
       · 润色-文风 × 5
       · 润色-AI味 × 5（读命中清单为工作起点）
       · 读者模拟 α/β/γ × 5
         ↓
  ⑤【修订 × 5】A段+C段硬禁用 100% 修；修订后再跑一次扫描器验证硬禁用清零
         ↓
  ⑥【Integrator · 整合审查】产《99_批次整合审查.md》+《90_事实表_预览.md》
         ↓                      └─→ 【下一批次 Primer/Ideator 可软重叠启动】
  ⑦【Merger · 事实表合并】原子写回 事实表 + 风险清单；与预览版对照标差异
```

**并发铁律（v2）**：
- ⓪①② 必须串行前置；⑥⑦ 必须串行后置；③④⑤ 高并发。
- **只有 Merger 可以写** `审查/事实表.md` 和 `审查/风险清单.md`。
- **跨批次软重叠**：批次 N 的 ⑥ 完成即可启动批次 N+1 的 ⓪①；但批次 N+1 的 ② 必须等批次 N 的 ⑦。
- **写作 subagent 不得互读同批次其他未落盘章节**；Best-of-N 三路写手互不读，Synthesizer 才读齐。
- **Primer 不得改 framework**；subagent 发现 context_pack 缺内容立即停下让主 agent 判断是否重跑。
- 写作 subagent 若与脑暴定稿冲突，**停笔报告主 agent**，不得自由发挥。

**旧四步闭环（04_审查工作流.md）**仍然有效：11 项审查维度、强制输出格式 A/B/C/D/E 段、修订口径不变；v2 只是在外层加了批次脑暴/整合，把 subagent 拆得更细，并引入确定性工具与软重叠。

## 五、每章交付标准（Definition of Done）

一章真正"写完"必须同时满足：
1. 字数 3,800–4,400（中文汉字数，由 `scripts/check_dod.py` 校验）。
2. 结构符合 `03_风格与创作铁律.md` 的单章模板。
3. 《硬校验报告》A 段为"无"或已全部修复，且末尾 F 段（事实表增量）已填。
4. 三份润色报告（节奏/文风/AI味）C 段中的"重 AI 味"全部修复。
5. `审查/第NNN章/AI味命中清单.txt` 的「硬禁用」段在修订后为 0 条（或本章在抒情豁免章号清单内）。
6. **`scripts/check_rhythm.py` 节奏闸 PASS**（破折号密度/短段比例/内括号心声/平均段长/字数标注偏差五项；详见 `06_AI味词库.md §1.4`）。
7. 所属批次的 Merger 已完成事实表合并（该章在 `审查/事实表.md` 章节完成度表中被标记为 ✅ 终稿）。
8. 章末"————本章字数：约 XXXX 字————"数字与实际相符（偏差 ≤ 150）。

## 六、每批次交付标准

一个批次真正"完成"必须同时满足：
1. 批次内 5 章全部满足上面的单章 DoD。
2. `审查/批次NNN_XXX-YYY/` 下齐全：`00_context_pack.md` / `00_批次脑暴定稿.md` / `01_创意稿.md` / `02_审核稿.md` / `99_批次整合审查.md` / `90_事实表_预览.md`（批次 0 无 01/02）。
3. 每章 `审查/第NNN章/` 下齐全：`AI味命中清单.txt` / `硬校验报告.md` / `润色报告_节奏.md` / `润色报告_文风.md` / `润色报告_AI味.md` / `读者反馈_α/β/γ.md`（批次 0 读者反馈可省）。
4. `99_批次整合审查.md` 无"需二次修订"章节遗留（若有，已完成二次修订）。
5. `审查/事实表.md` 与 `审查/风险清单.md` 已由 Merger 原子写更新；事实表预览 vs 正本的差异（如有）已入风险清单。
6. 批次末好感度实际值与脑暴定稿目标值偏差 ≤ 5，或已在 99 中解释原因。

## 七、确定性工具使用约定

`scripts/scan_ai_templates.py` 是全项目的 AI 味硬检查器，**主 agent 亲自调用**，不是 subagent：

```bash
# 扫单章（章号/路径）
python scripts/scan_ai_templates.py 007
python scripts/scan_ai_templates.py 正文/第007章_广播站报到.txt

# 扫批次
python scripts/scan_ai_templates.py --batch 010-014

# 全书批量
python scripts/scan_ai_templates.py --all
```

调用点：
- **③.5**：写作产出后、审查开始前，自动扫描本批 5 章。
- **⑤ 修订之后**：主 agent 再跑一次，验证"硬禁用段清零"。
- **债务清理 / 批次 0**：先对已有章节全量扫一遍。

词库更新只改 `framework/06_AI味词库.md`，脚本端的规则表跟它在同一处维护（`scan_ai_templates.py` 顶部常量）。新增高频 AI 味模板建议两处都更新，保证工具与人双通道同步。
