# 批次化写作工作流（并发生产线 · v3）

> 本文件是所有"批次 subagent"的宪法。v3 相对 v2 的变更（自动化改造）：
> 1. **章级粒度流水线**：写完一章即可扫 + 审 + 修，不等批次内其他章。只有 ⑥⑦ 在批次末汇合。
> 2. **state.json 为批次唯一真相源**：每步 subagent 用 `scripts/state.py set-chapter ...` 更新状态；主 agent 读 state 决定下一步。
> 3. **所有 subagent 必须按 `framework/09_subagent返回协议.md` 产 RETURN_JSON 尾段**，主 agent 不再人眼读报告。
> 4. **硬 Quality Gate**：`scripts/check_dod.py` 检验章级 DoD，不过 gate 自动触发重修订，不问用户。
> 5. **自动升级规则**：主 agent 何时能自决、何时停下来问用户，由 `framework/08_自动升级规则.md` 硬编码。
> 6. **事实表双文件**：`审查/事实表.md`（人读）+ `审查/facts.json`（机读）。Merger 原子写两份；`scripts/check_facts.py` 做 canon 冲突检测。
>
> v2 遗留设定（Primer / Best-of-N / 三路润色 / 读者模拟 α/β/γ / Integrator 预览 / 跨批次软重叠）全部保留。
>
> 优先级：`04_审查工作流.md` 的 11 项维度与输出格式永远有效；本文件定义调度、并发、角色分工。

## 〇、全局协议（v3 新增，所有角色必读）

### 0.1 最终返回格式统一（强制）

本文件下面所有 subagent 模板里出现的 `## 最终返回（N 行）` **全部替换为**：

```
## 人读摘要
<= 3 行自然语言。

## RETURN_JSON
{单行合法 JSON，字段见 framework/09_subagent返回协议.md §三}
```

主 agent 用正则 `^##\s+RETURN_JSON\s*\n(.+?)$` 抓取并 `json.loads`。**不产 RETURN_JSON 的 subagent 视为失败**。

### 0.2 状态机写入（强制）

每个 subagent 交稿前调用一次：

```bash
python3 scripts/state.py set-chapter NNN CCC \
    stage=<writing|scanned|reviewing|revising|ready|done> \
    <其它字段>
```

或批次级：

```bash
python3 scripts/state.py set-batch NNN <key>=<value>
```

state.json 是批次唯一真相源（schema 见 `scripts/state.py` 顶部注释）。主 agent 只读 state 决定下一步，不读 markdown 报告的叙述性文字。

### 0.3 章级粒度（v3 新）

- 一章写完就立即扫/审/修这一章；不等同批次的其它章。
- 仅 ⑥ Integrator 必须等 5 章都 `dod_passed=true`。
- 硬 Quality Gate `scripts/check_dod.py NNN CCC` 在 ⑤ 修订之后运行；未过 gate 自动再派一次修订；连续 2 次未过触发 `framework/08_自动升级规则.md` 的 R5.2，停并告知用户。

### 0.4 F 段双产出（硬校验 subagent，v3 新）

硬校验在产 `硬校验报告.md` 的 F 段同时，必须**并产** `审查/第NNN章/F.delta.json`（schema 见 `framework/09` §五），供 Merger 与 `check_facts.py` 机读合并。

### 0.5 Primer 锚样轮换（v3 新）

`context_pack.md §5 锚样` 的 2–3 段示例段，**每批次必须轮换**，避免写手因长期模仿同几段而漂移风格。

Primer 选取锚样的口径：
- 从"已走闭环"的章节池里，随机抽 2 段 + 上批次口碑最高 1 段（读者均分最高）。
- 同一段锚样不得跨 3 个连续批次出现。
- 锚样 ID 写进 `state.batch_artifacts.anchor_sample_ids`，便于追溯。

### 0.6 确定性工具链总表（主 agent 速查）

| 工具 | 何时跑 | 产出 | exit 码含义 |
|-----|-------|------|-----------|

章级粒度的标准单章生命周期（v3 主 agent 自决）：

```
pending
  ↓ 派写作 subagent（单写手或 Best-of-N + Synthesizer）
writing
  ↓ 落盘后主 agent 自动跑 check_format + check_rhythm + check_seam + scan_ai_templates + parse_chapter
  ↓ check_rhythm/check_format FAIL 直接打回 writing 重写（不进入 ④）
scanned
  ↓ 7 路并发审查（硬校验 + 3 路润色 + 读者 α/β/γ）
reviewing
  ↓ 等全部 RETURN_JSON 到齐，派 ⑤ 修订
revising
  ↓ 修订落盘后主 agent 自动跑 scan + check_rhythm + check_dod
ready  ←────── 未过 gate 回 reviewing 再派修订（最多 2 次后升级用户）
  ↓ 等全批次 ready
（批次级）→ Integrator → Merger → 批次 done
```

### 0.7 主 agent 反偷懒铁律（v3.1，2026-04-26 复盘加入）

> 背景：批次 002–004 出现"主 agent 自己当写手、跳过整套流水线"的事故，
> 11 章中 9 章未达 DoD（字数）+ 节奏闸 6 项严重违规。
> 本节是对主 agent 自身行为的硬约束。

**铁律 1：主 agent 不得自任写手**
- 写章必须派 ③ 写作 subagent；主 agent 只负责派单 + 校验 + 集成。
- 例外：单段 ≤ 200 字的衔接补丁（如 ⑤ 修订时改一段对话），可主 agent 直接改；超出立刻派 subagent。

**铁律 2：闸门不可跳**
- 写完一章 ≠ 章节"落盘完成"。落盘后必须立刻按下表跑 5 个工具，**任一 FAIL 禁止开下一章**：

| 顺序 | 工具 | FAIL 处置 |
|----|-----|----------|
| 1 | `check_format.py` | 退回写作 subagent 重写 |
| 2 | `check_rhythm.py`（**v3.1 新闸**） | 退回写作 subagent 重写 |
| 3 | `scan_ai_templates.py` + 看「硬禁用」段 | 派 ④润色-AI味 |
| 4 | `check_seam.py` | 派 ⑤修订改衔接 |
| 5 | `check_dod.py`（修订后） | 派 ⑤修订；连 2 次 FAIL 触发 R5.2 升级 |

**铁律 3：批次锁——单会话最多连写 3 章**

主 agent 在同一对话会话里：
- **连续派出的写作 subagent 不得超过 3 章**（含 Best-of-N 视为 1 章）。
- 超过 3 章必须停下来：
  1. 跑当前批次 `check_rhythm.py --batch NNN-MMM` 抽检风格漂移
  2. 跑 `check_voice.py --baseline 1-10 --target NNN-MMM`
  3. 把 3 章中**最低质量的 1 章**初稿展示给用户审阅
  4. 收到用户 OK 或定向修订指示后，才能进入下 3 章

**铁律 4：章末字数标注必须实测**

写作 subagent 在写"————本章字数：约 XXXX 字————"时，**XXXX 必须是该 subagent 调用 `_count_chinese()` 函数（或同等规则）的实测结果**，不得估算。差异 ≤ 50。

**铁律 5：风格漂移报警**

每完成 3 章，主 agent 必须跑：
```bash
python3 scripts/check_voice.py --baseline 1-10 --target NNN-MMM
python3 scripts/check_rhythm.py --batch NNN-MMM
```

任一指标比 010-014 基线偏离 > 30%（红色）或 > 20%（黄色），主 agent 必须**强制停笔**，把对比报告呈给用户决定是否回校。

## 一、批次的定义

- **一个批次 = 连续 5 章**，编号必须连续（例：006–010、011–015）。
- **批次 0 = 债务清理批次**（首次专用）：不写新章，对历史章节补跑④⑤⑥⑦。
- 目录命名：`审查/批次NNN_XXX-YYY/`，NNN 三位批次号，XXX-YYY 本批首末章号。

## 十一、并发铁律（v3，覆盖 v2 §十）

1. **章级粒度并发（v3 新）**：③ 写完一章即可立即跑 ③.5 → ④ → ⑤（该章独立推进），**不需要等同批次其他章**。
   - 例：第 010 章写完后，主 agent **立刻**扫+审+修第 010 章，同时第 011/012 章还在写。
   - 只有 ⑥ Integrator 是批次级汇合点（须等全 5 章 dod_passed）。
2. **同批次内串行**：⓪ Primer → ① Ideator → ② Gatekeeper 必须串行前置；⑥ Integrator → ⑦ Merger 必须串行后置。
3. **章内 ④ 全并发**：硬校验 + 润色-节奏 + 润色-文风 + 润色-AI味 + 读者 α/β/γ = **7 路**可同时派。⑤ 修订必须等本章 7 份报告齐全。
4. **写文件独占权**：
   - `审查/事实表.md` + `审查/facts.json` + `审查/风险清单.md`：只有 Merger 可写。
   - `framework/` 下任何文件：主 agent 专属，所有 subagent 只读。
   - `审查/批次NNN_XXX-YYY/state.json`：每个 subagent 交稿时调用 `scripts/state.py set-chapter ...` 写，冲突时**最后写入胜出**（章级字段互相独立不会碰撞）。
   - `审查/批次NNN_XXX-YYY/` 下其它文件的写权限见 §四目录规范。
4. **跨批次软重叠（v2 新增）**：
   - 批次 N 的 Integrator 完成后，**可以**启动批次 N+1 的 ⓪ Primer 和 ① Ideator。Primer 读 90_事实表_预览.md 而不是事实表正本。
   - 但批次 N+1 的 ② Gatekeeper **必须等** 批次 N 的 ⑦ Merger 完成（Gatekeeper 要引用正本做一致性判断）。
   - 若 Merger 发现预览与正本偏差大（风险清单有新增），批次 N+1 的 Primer 必须重跑。
5. **写作 subagent 不得互读**：5 个写作 subagent（或 Best-of-N 的三路）**不能**读同批次其他尚未落盘的章节。衔接靠脑暴定稿 + context_pack §4。
6. **Best-of-N 三路写手不得互读**：写手 A/B/C 产出 drafts/ 下三稿，互不读；Synthesizer 才读齐三稿。
7. **修订 subagent 不得扩写到 > 4,400 字**。
8. **Primer 不得改 framework**：若 framework 本身不完整，Primer 停止打包，上报主 agent。

## 十二、异常与回退（v2）

| 情况 | 处理 |
|-----|-----|
| Primer 产出的 context_pack 被后续 subagent 反复投诉"缺内容" | 重跑 Primer 一次；若仍不行，升级主 agent 检查 framework 是否该补 |
| 扫描脚本崩溃或词库文件损坏 | 跳过 ③.5，润色-AI味 subagent 回退到自行扫描（v1 行为） |
| 三路润色意见严重冲突 | Integrator 拍板，写进 99_批次整合审查.md §8；若 Integrator 也拿不定，升级主 agent |
| Best-of-N 三稿中有一稿质量明显差（例：字数不够、跑题） | Synthesizer 只用另外两稿合成；**不**重跑失败写手，除非剩下两稿合起来也 < 3,800 字 |
| 读者反馈平均分 < 5 | 主 agent 决定：二次修订 or 重跑 Ideator+Gatekeeper（认定脑暴定稿本身有问题） |
| 批次 N+1 预览启动后，Merger 发现预览 vs 正本偏差巨大 | 冻结批次 N+1 已启动的 Primer / Ideator 产物；Primer 重跑、Ideator 重跑；风险清单记录一条"软重叠偏差" |
| Ideator 产出质量低（只复述细纲） | Gatekeeper 判"需重做"；2 次不改升级主 agent |
| 5 章写作中某一章失败 | 只重派该章写作 subagent（日常档）或重跑一路写手（Best-of-N 档） |
