# 自动升级规则（主 agent 自决边界合同 · v1）

> 本文件是**主 agent 与用户之间的合同**。
> 规则以外的情况主 agent 自动处理，**不打断用户**；命中规则中的"停"字样才升级。
> 目的：把"什么时候催、什么时候不催"从人的判断变成硬规则，减少用户催促。

---

## 一、术语

- **自动动作**：主 agent 自己派 subagent / 跑脚本，不问用户。
- **计数**：`state.json.chapters.<ch>.retry_counts` 字段，跨多次运行持久。
- **升级用户**：主 agent **停下来**，用清晰的一段话告知用户"哪里卡住 + 建议选项 A/B/C"，等用户回复。
- **规则编号**：R<阶段>.<序号>，便于在 `state.escalations[].rule` 里回溯。

## 三、升级消息格式（主 agent 专用）

触发"✅ 升级"时，主 agent **必须**按以下格式一次性输出：

```
⚠️ 流水线暂停 · 等待用户决定
规则：<R5.1>
批次：<001>  章节：<013>  阶段：<修订>
现象：<修订后 check_dod 仍未过，连续 2 次>
已尝试：<列出已做的自动动作>
当前 state：<摘要>

建议选项：
A. <具体动作，例：改口派 Best-of-N 三写手重写第 013 章>
B. <具体动作，例：修改 framework/03 §三（单章模板）后重启>
C. <具体动作，例：回退到上一版，让我接管调试>

请回复 A / B / C 或自行指示。
```

---

## 四、降级规则（✅ → ❌）的条件

若用户在升级消息里说"**以后这类问题你自己处理**"或"**类似情况免问**"，主 agent 将该规则编号写入 `state.batch_auto_overrides: [R5.1, ...]`，**本批次内**该规则不再升级。跨批次不继承（新批次恢复默认）。
