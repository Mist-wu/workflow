## 核心观点

1. **Harness的重要性：** Harness解决AI Agent的长期运行稳定性、状态连续性和任务可靠性。
2. **两大范式：** React是走一步看一步（动态自适应），PlayAct是先规划再执行（稳定高效）。
3. **范式选择：** 不确定性任务→React，确定性长任务→PlayAct，复杂实践→混合模式。
4. **多Agent架构：** 分层（控制器、任务、执行器）+ 协作（父子、并行、竞争）。
5. **Agent核心难点：**
   - **状态管理：** 保存任务状态、中间结果、工具调用记录和LLM推理结果。
   - **记忆系统：** 从固定上下文发展到分层、结构化、可进化的复杂系统。
6. **后端工程能力是基石：** AI Agent开发本质上是后端工程的分支。

## 可执行建议

1. 深入理解并实践Harness来提升Agent的稳定性。
2. 掌握React和PlayAct两种范式，尝试在不同任务中应用。
3. 结合实际项目探索混合范式的优势。
4. 强化状态管理和记忆系统设计。
5. 引入沙箱、权限控制等安全机制。
6. 重点提升后端工程能力（系统架构、并发处理、监控部署）。

## 需要警惕

1. **React效率问题：** 灵活但迭代多，对效率要求高的场景需谨慎。
2. **PlayAct灵活性不足：** 规划出错可能全盘皆错。
3. **早期记忆系统局限性：** 固定上下文窗口容易遗忘。
4. **Agent运行安全风险：** 需要完善的安全保障机制。
